# Decisions

- Keep the product site dependency-free: plain HTML, CSS, and JavaScript remain enough for the current public foundation.
- Present the interactive router and product surfaces as one cohesive, polished product story.
- Use GitHub as the current source of truth for the project brief, roadmap, discussions, issues, security reporting, and license.
- Use Cloudflare Pages as the primary public host at `hot-potato-32c.pages.dev`; keep GitHub as the source of truth and GitHub Pages as a secondary preview while the permanent domain is undecided.
- Do not use `gethotpotato.com` or its email domain: that domain belongs to an unrelated active product. A permanent product name and domain need separate diligence.
- September 24, 2026: remove the integration logo wall and tiles, hosted pricing/support tiers, and broad availability guarantees. Describe the application as open source and in development, and refer setup questions to its documentation. This replaces the earlier informational-integration-tile approach.
- Label the interactive example as simulated before playback and the rule sketch as pseudocode. Preset leads, calendar times, and animated outcomes do not establish live provider behavior.
- Product, setup, and application-license links use `harrisonoconnorhover/hot-potato`. This `HotPotato` repository is the separately MIT-licensed marketing site; the application is AGPL-3.0-only.

- September 25, 2026: scope public capability claims to published application commit `8bd272e`, not the unpublished local backlog. Replace the earlier pseudocode with actual rule conditions and link the synthetic input/outcome case to that commit’s source, assertions, and CI. Saved rule IDs do not justify historical rule-version claims.
