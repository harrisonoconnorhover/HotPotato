# Hot Potato roadmap

This roadmap is product direction, not a promise of availability or timing. Each phase should leave one small, useful vertical slice working before the next begins.

## 0. Public foundation — current

- Publish the product thesis, interactive simulation, and honest release status.
- Establish the public repository, contribution path, security policy, and license.
- Collect real inbound-routing workflows through GitHub Discussions.

## 1. Explainable routing core

- Accept a documented lead payload.
- Evaluate deterministic territory, ownership, and fallback rules.
- Return an owner plus a plain-language decision trace.
- Ship local examples and focused automated tests.

## 2. First end-to-end route

- Read account ownership from HubSpot.
- Resolve Google Calendar availability.
- Select a rep and write the explained result back to HubSpot.
- Provide a local self-hosting path and failure visibility.

## 3. Buyer-facing scheduling

- Embed a lightweight availability surface after form submission.
- Support safe retries, capacity rules, and meeting creation.
- Add operator-facing route search and rule-version history.

## 4. Managed option

- Validate whether teams want hosted operation before defining packaging.
- Publish pricing only after the managed product and support boundary exist.

## Not planned yet

- A general-purpose workflow builder
- A marketplace of speculative integrations
- Enterprise packaging before the routing core is useful
