02 / HOW IT WORKS

Routing logic
you can actually read.

The public application matches ordered rules, preserves an eligible existing owner, and otherwise uses weighted assignment. The rule below comes from its routing tests.

✦ EXAMPLE EXPLANATION

Why did Maya go to Jamie?

✓ Northstar Labs matched Enterprise
✓ Northeast territory narrowed the pool to 4 reps
✓ No existing CRM owner was found
✓ Jamie had the highest weighted priority
✓ Jamie was available at the requested time
Fictional example. Saved decisions identify the matched rule, assigned rep, and assignment reason. They do not preserve a historical rule snapshot.

One routing decision, with evidence.

The design problem: assign a qualified lead once, respect an eligible existing owner, and return a clear failure when no one can take it. Matching and rep selection are separate from the database and provider calls, so the core decision can be checked with fixed inputs.

In the public tests, a fictional 900-person New York company arrives Monday at 12:00 UTC. Ada and Marcus each have two assignments; their weights are 2:1, so Ada is selected. Set Marcus as the existing owner and Marcus is preserved. Mark Ada busy and Marcus is selected. On Sunday, outside both reps’ schedules, the same lead returns NoEligibleRepError.

04 / PROJECT STATUS

Open source.
In development.

Hot Potato is software you run and configure yourself. This site offers a preset illustration and an inspectable routing case from the public application.

Run it yourself

The linked public version covers lead assignment, saved decisions, Google availability checks, and queued HubSpot owner updates. Setup and provider credentials are required for external actions.

Public scope

Meeting booking, an editable routing studio, and detailed rule/rep previews exist only in later local development. They are not included in the public version linked here. Live provider operation has not been demonstrated by this website.
